# Claude Code チートシート

本研修で使う Claude Code（VS Code 拡張）の操作をまとめます。
画面の表示や名称は拡張機能のバージョンによって変わることがあります。見つからない場合は講師に確認してください。

## 基本操作

| やりたいこと | 操作 |
| :--- | :--- |
| チャットパネルを開く | サイドバー、またはエディタ右上の Claude アイコン |
| 新しい会話を始める | チャットパネル上部の新規会話ボタン、または `/clear` |
| 過去の会話に戻る | チャットパネルの履歴ボタン |
| ファイルを渡す | 入力欄で `@` に続けてファイル名（例：`@vibe-order/docs/requirements.md`） |
| 選択中のコードについて聞く | エディタでコードを選択してから質問する |
| コマンドを呼び出す | 入力欄で `/` を入力し、候補から選ぶ（例：`/selfcheck`） |
| 処理を止める | 実行中に表示される停止ボタン、または `Esc` |

## モード（入力欄で切り替え）

| モード | 動き | 研修での使いどころ |
| :--- | :--- | :--- |
| 編集前に確認 | ファイルを変更する前に毎回確認する | 慣れないうちの標準 |
| 自動で編集（Edit automatically） | ファイルの編集を自動で承認する | Day1 の Vibe Coding、Day3 以降の計画承認後の実装 |
| Plan モード | ファイルを変更せず、調査と計画だけを行う | Day2 午後以降、作業の最初は必ずここから |

## プロジェクト設定ファイル

| ファイル | 役割 | 書籍（Cline）での対応 |
| :--- | :--- | :--- |
| `CLAUDE.md` | AI が毎回読むプロジェクトのルール | `.clinerules/*.md` |
| `.claude/commands/*.md` | `/ファイル名` で呼び出せる指示のテンプレート。`$ARGUMENTS` に引数が入る | Workflows |
| `.claude/settings.json` | 権限設定。`deny`（禁止）、`ask`（確認）、`allow`（自動許可） | `.clineignore`、Auto-approve |
| `.mcp.json` | 外部ツール（MCP サーバー）の設定 | `cline_mcp_settings.json` |

> [!NOTE]
> 設定ファイルを変更したら、新しい会話を始めてから試してください。

## 書籍の用語との対応

| 書籍（Cline） | 本研修（Claude Code） |
| :--- | :--- |
| Plan モード / Act モード | Plan モード / 計画を承認して実行 |
| `/deep-planning` | Plan モードで計画を依頼する |
| Focus Chain | Todo リスト（AI が作業の進み具合を表示する） |
| `@/path/to/file` | `@path/to/file` |
| `@terminal` | ターミナルの出力をコピーして貼り付ける |
| Amazon Bedrock、Gemini の API 設定 | 社内契約の Claude アカウントでサインイン |

## よい指示のコツ

*   **目的、仕様、制約**を書く（何のために、何を、何をしてはいけないか）
*   **完了条件**を書く（どのコマンドが成功すれば完了か）
*   いきなり実装させず、**まず計画を出させる**
*   1回の依頼は30分で終わる大きさにする
*   エラーは要約せず、**出力をそのまま**貼り付ける
*   AI の説明が分からなければ、遠慮なく質問する（「なぜそのライブラリを選んだの？」）

## 困ったとき

| 症状 | 対処 |
| :--- | :--- |
| 同じ失敗を繰り返す | 一度止めて、新しい会話で状況を整理してから再開する |
| 指示を忘れている | CLAUDE.md に書く、または会話をリセットして必要なファイルだけ `@` で渡す |
| 大量に変更されて追えない | `git --no-pager diff --stat` で確認し、不要なら `git restore` で戻す |
| サインインできない | Codespaces のブラウザがポップアップをブロックしていないか確認し、講師に連絡する |
