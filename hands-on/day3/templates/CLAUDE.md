# プロジェクトルール

このファイルは Claude Code が毎回読み込むプロジェクトのルールです。
書籍 PART5〜6 の Cline Rules（`common.md`、`coding.md`）を Claude Code 向けに書き換えたものです。

## Policy

- セキュリティを最優先とし、低下の恐れがあれば作業を止めて合意を得る
- KISS原則に従う
- 各タスクの分割単位は最長30分
- 以下の変更時は必ず `vibe-order/docs/memo.md` に記録する
  - コメントアウト
  - 処理削除
  - ライブラリ変更
- 依存パッケージは極力増やさず、追加時は標準機能で代替可能かを検討する
- 新規にライブラリを導入する場合、ライセンスは MIT、Apache-2.0、BSD のみとする
- Git Commit / Push は明示的な依頼がある場合のみ行う

## 開発スタイル

- 既存コードベースの尊重
  - 重複実装の禁止。実装前に既存コードを確認し、重複がないかを確認する
- コード変更は関係がある箇所のみ
  - リファクタリングが必要な箇所は、実装せず指摘のみに留める
- Debug は1観点ずつ行う。他の観点を試す前に、必ず元の状態に戻す
- 分からないライブラリの使い方は、推測せず `vibe-order/docs/ref/` の `llms.txt` を参照し、根拠を引用する

## Test

- Kent Beck 準拠の TDD を順守する（Red → Green → Refactor）
  - 処理変更のたびに `npm run test` を実行し、常に成功させる
  - Formatter / Linter も常に通す（`npm run check`）
- E2E テストは、すべての unit test が成功した後の最終チェックとする
  - テストデータは毎回リセット可能にし、他テストと状態を共有しない

## Taskの完了条件

- デグレードがないことを確認する
- Format / Lint / Test が一貫して成功している
- テストカバレッジは80%以上を必達、100%を目指す
  - カバレッジ取得コマンド: `npx vitest --run --coverage`

## Tips

- 実行コマンドは CI と同じものを使う
- CLI は Pager を使わない（例: `git --no-pager diff`）
- 計画が合意されたら `/save-plan` で保存する
